## Живой HTTP-сервер

Сервер запущен командой `python -m cinema` на 127.0.0.1:8000 с отдельной базой проверки. GET / и /api/health вернули 200. check_health.py сообщил OK HTTP and database. backup.py создал и проверил копию работающей базы.

`scripts/demo_api.py` прошёл весь сценарий:

```text
POST /api/auth/login -> 200
POST /api/admin/movies -> 201
GET /api/movies/4 -> 200
PUT /api/admin/movies/4 -> 200
PATCH /api/admin/movies/4 -> 200
POST /api/auth/register -> 201
GET /api/screenings -> 200
GET /api/screenings/1/seats -> 200
POST /api/bookings -> 201
GET /api/bookings/2 -> 200
DELETE /api/bookings/2 -> 204
DELETE /api/bookings/2 -> 204
GET /api/bookings/2 -> 200 (cancelled)
```

Числовые идентификаторы зависят от содержимого базы. Проверочные данные не включены в готовый архив.

## Контракт и конфигурация

OpenAPI 3.0.3 проверен через openapi-spec-validator. Все 22 документированные операции сопоставлены с маршрутами в обоих направлениях. Оба Compose-файла прошли разбор YAML. Инструменты валидации использовались только при проверке и не добавлены в зависимости проекта.

На исходной Windows-машине Docker отсутствовал. Дополнительная проверка контейнера на macOS описана ниже; публичный сертификат и настройки отдельного сервера требуют приёмки из deployment.md.

## Дополнительная проверка на macOS

После исправлений команда `python3 -m unittest discover -s tests -v` завершила 28 тестов успешно. Новые тесты подтверждают, что `/api/health` возвращает HTTP 503 при отсутствии БД без создания пустого файла и что смена переменной ADMIN_PASSWORD не скрывает учебный пароль в старой БД. JavaScript прошёл синтаксическую проверку; при часовом поясе компьютера UTC сеанс `12:00Z` отображается как `15:00` по Москве.

Оба варианта Compose прошли `docker compose config -q` с заданными паролем и доменом. Без ADMIN_PASSWORD конфигурация теперь отклоняется. Запуск на сетевом адресе с учебным паролем также отклонён до создания БД. Docker-образ собран и запущен локально; процесс работает от пользователя cinema, `/api/health` и `/api/movies` вернули HTTP 200. Скрипт `scripts/demo_api.py` прошёл живой сценарий GET, POST, PUT, PATCH и DELETE внутри тестового контейнера. После проверки контейнер остановлен; публичный HTTPS и настройки внешней сети не проверялись.
