# Архитектура веб-приложения кинотеатра

## Состав монолита

HTTP-сервер принимает запрос, сопоставляет маршрут, проверяет роль и формирует JSON-ответ. Сервисный слой выполняет бизнес-правила и транзакции. Слой данных открывает короткоживущие соединения SQLite и включает внешние ключи. Статический интерфейс использует тот же origin и обращается к REST API через `fetch`.

```text
Браузер
  ├─ HTML, CSS, JavaScript
  └─ fetch /api/*
          │
          ▼
WSGI маршрутизация и защита HTTP
          │
          ▼
CinemaService — правила и транзакции
      ├─ TTL-кэш каталога
      └─ Database — параметризованный SQL
                    │
                    ▼
                  SQLite
```

## Серверная логика

`cinema.web` отвечает за маршруты, JSON, cookies, CSRF, роли, лимит тела запроса, ETag, gzip и защитные заголовки. `cinema.service` содержит операции каталога, заказов и администрирования. `cinema.db` создаёт схему, тестовые данные и соединения. Такое разделение позволяет тестировать сервис напрямую и API через WSGI без браузера.

## Клиентская логика

Интерфейс загружает пользователя, фильмы и сеансы после открытия страницы. Фильтры формируют query-параметры API. Даты и время отображаются по Москве; введённое администратором время сеанса также трактуется как московское. Схема мест строится из массива мест; занятые кнопки отключены. Выбранные идентификаторы отправляются одним запросом. После заказа или отмены интерфейс перечитывает личный кабинет и расписание. Пользовательские значения добавляются через `textContent`, поэтому они не интерпретируются как HTML.

## Аутентификация и авторизация

Пароль проверяется по хешу `scrypt` либо PBKDF2-HMAC-SHA256, если системная сборка Python не предоставляет `scrypt`. После входа сервер создаёт случайный токен, сохраняет только его SHA-256 хеш и отправляет исходное значение в `HttpOnly` cookie. Отдельный CSRF-токен передаётся в JSON и добавляется клиентом в заголовок изменяющих запросов. Роль проверяется на сервере для каждого административного маршрута; скрытие панели в интерфейсе служит только удобству.

## Производительность

Каталог и расписание кэшируются на 30 секунд и получают ETag. Изменение фильмов, залов, сеансов или цены очищает кэш. Ответы больше 1 КБ сжимаются gzip. WAL разрешает конкурентные чтения во время записи. Схема мест всегда читается из базы и поэтому отражает актуальную занятость.
