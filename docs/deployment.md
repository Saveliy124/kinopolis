# Развёртывание кинотеатра · практические №7–8

## Среда и права

Локально приложение работает на macOS, Linux и Windows с Python 3.9+. Для отдельного сервера выбран Linux с Docker Compose: один контейнер приложения, SQLite в постоянном томе. Контейнер запускается от системного пользователя cinema; Dockerfile создаёт этого пользователя и выдаёт ему права на /data. Приложению не нужны сторонние Python-пакеты.

## Локальный запуск

1. Распаковать весь проект и выполнить `python3 -m cinema` на macOS/Linux либо запустить START.cmd или `python -m cinema` на Windows.
2. Оставить терминал открытым и перейти на `http://127.0.0.1:8000/`.
3. В другом терминале выполнить `python scripts/check_health.py`.
4. Проверить вход, бронь, отмену и повторный выбор освобождённого места.

База создаётся в data/cinema.db. Сервер слушает локальный интерфейс, поэтому для такой демонстрации SSL не требуется. Для отдельной учебной базы в PowerShell:

```powershell
$env:CINEMA_DB = 'data/demo.db'
python -m cinema
```

Если порт занят: `python -m cinema --port 8001`. Тогда открыть `http://127.0.0.1:8001/` и проверять `python scripts/check_health.py --url http://127.0.0.1:8001/api/health`. Остановка — Ctrl+C.

## Docker на Linux-сервере

Администратор обновляет ОС штатным пакетным менеджером, устанавливает Docker Engine и Compose plugin, загружает проект в отдельную папку. SSH-доступ ограничивается ключами и доверенными адресами. Внутри контейнера используется пользователь cinema без root.

```text
cp .env.example .env
```

Задать собственный ADMIN_PASSWORD в .env до первого запуска базы. Если пароль пуст или переменная отсутствует, Compose откажется запускать приложение. Сервер также отклоняет запуск на сетевом адресе, если учебный пароль Admin123! сохранился у администратора в существующей БД. Для публичного размещения используйте отдельную БД, созданную с новым паролем. Затем:

```text
docker compose up --build -d
docker compose ps
docker compose logs --tail=50 cinema
docker compose exec cinema id
docker compose exec cinema python -c "import urllib.request; print(urllib.request.urlopen('http://127.0.0.1:8000/api/health').read().decode())"
```

Команда id должна показать пользователя cinema, health check — `{"status":"ok"}`. В основном Compose порт опубликован только на 127.0.0.1:8000. Данные сохраняются в томе cinema_data. ADMIN_PASSWORD используется при создании администратора и не меняет пароль существующей записи.

## Публичный HTTPS и сеть

Вариант с Caddy подготовлен в deploy/. Перед его запуском направить DNS реального домена на сервер. Открыть входящие TCP 80/443. Порт 8000 наружу не открывать. SSH разрешить только доверенным адресам. При использовании UFW сначала разрешить свой SSH-доступ и 80/tcp, 443/tcp, проверить правила и только затем включать брандмауэр. Обновления ОС и образов выполняет администратор.

Добавить `CINEMA_DOMAIN=ваш.домен` в .env и выполнить из корня проекта:

```text
docker compose -f docker-compose.yml -f deploy/docker-compose.https.yml up --build -d
```

Caddy получает сертификат для домена и перенаправляет HTTP на HTTPS. Дополнительный Compose включает COOKIE_SECURE=1 у приложения. Сертификаты сохраняются в томе Caddy. Проверить HTTPS в браузере, вход, бронь и `python scripts/check_health.py --url https://ваш.домен/api/health`. Выдача сертификата требует реального домена и доступного ACME. Для локального HTTP основной Compose оставляет COOKIE_SECURE=0.

## Мониторинг и управление

Dockerfile проверяет /api/health каждые 30 секунд, таймаут — 3 секунды, три попытки. Endpoint проверяет доступность существующей БД и таблицы фильмов, не создавая новую БД при сбое. Состояние видно в `docker compose ps`, логи — `docker compose logs -f cinema`. Ответ содержит X-Request-ID; необработанные ошибки пишутся с этим идентификатором. Изменения администратора сохраняются в audit_log.

`restart: unless-stopped` поднимает контейнер после завершения процесса. Состояние unhealthy само по себе контейнер не перезапускает: нужно проверить логи, диск и права тома. scripts/check_health.py возвращает код 0 при успехе и 1 при сбое и подходит для вызова из серверного мониторинга.

Обновление: сделать backup, выполнить `docker compose up --build -d`, затем health check и цикл брони. Остановка с сохранением данных — `docker compose stop`. Для обычного обновления тома не удаляются.

## Резервное копирование

Для локальной работающей базы:

```text
python scripts/backup.py
```

Для конкретных путей: `python scripts/backup.py --database data/cinema.db --output backups/before-update.db`. Скрипт использует SQLite Backup API, учитывает WAL, проверяет integrity_check и не перезаписывает существующий файл. Простое копирование одного .db у работающей WAL-базы не гарантирует полноту.

Для контейнера:

```text
docker compose cp scripts/backup.py cinema:/tmp/backup.py
docker compose exec cinema python /tmp/backup.py --database /data/cinema.db --output /data/before-update.db
docker compose cp cinema:/data/before-update.db ./cinema-before-update.db
```

Копии хранить вне публичных папок с доступом только администратора. Для восстановления остановить приложение, сохранить текущие .db, -wal и -shm в отдельной папке, установить проверенную копию вместо основной БД без старых sidecar-файлов, вернуть права cinema и запустить приложение. Проверить health и заказы.

## Фактическая проверка

На Windows проверены живой HTTP-сервер, интерфейс, health и резервное копирование. На macOS дополнительно собран и запущен Docker-образ: контейнер работает от пользователя cinema, health и каталог отвечают, REST-сценарий проходит. Правила внешнего брандмауэра и выдача публичного сертификата не проверялись. Команды и критерии проверки целевого сервера приведены выше.
