# Веб-приложение для кинотеатра

Монолитное учебное приложение для практических занятий 1–12 по дисциплине «Создание программного обеспечения». Гость просматривает фильмы и расписание. Пользователь регистрируется, выбирает места, бронирует или покупает билеты и отменяет действующую бронь. Администратор добавляет фильмы и залы, создаёт сеансы и меняет цены. Покупка учебная, без списания денег.

Проект не требует сторонних библиотек: сервер, REST API и работа с SQLite построены на стандартной библиотеке Python 3.9 и новее.

## Быстрый запуск

На macOS и Linux выполните из папки проекта:

```text
python3 -m cinema
```

На Windows запустите **START.cmd** двойным щелчком либо выполните:

```text
python -m cinema
```

Откройте `http://127.0.0.1:8000`. При первом запуске создаются база данных, тестовые фильмы, залы, сеансы и учётная запись администратора:

- адрес: `admin@cinema.local`
- пароль: `Admin123!`

Для учебного локального запуска эти значения удобны. При запуске на сетевом адресе сервер не принимает учебный пароль, в том числе если он сохранился в ранее созданной БД. Docker Compose требует указать собственный `ADMIN_PASSWORD` в `.env` до первого запуска. Переменная не меняет пароль уже существующего администратора; для публичного размещения используйте отдельную БД, созданную с новым паролем.

Окно сервера должно оставаться открытым. Если браузер пишет «Не удаётся получить доступ к сайту», проверьте, что сервер запущен, и откройте именно `http://127.0.0.1:8000/` (HTTP). Остановка — Ctrl+C. Если порт занят, запустите `python3 -m cinema --port 8001` на macOS/Linux или `python -m cinema --port 8001` на Windows, затем откройте `http://127.0.0.1:8001/`.

Готовая копия не содержит старых учётных записей и заказов: при первом запуске создаётся новая учебная база и сеансы на ближайшие дни. Исходный ZIP остаётся без изменений. Если позднее все сеансы прошли, добавьте будущие через панель администратора.

Даты и время сеансов в интерфейсе указываются по Москве (МСК), независимо от часового пояса компьютера.

## Настройки

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `CINEMA_DB` | `data/cinema.db` | Путь к файлу SQLite |
| `CINEMA_HOST` | `127.0.0.1` | Адрес прослушивания |
| `CINEMA_PORT` | `8000` | Порт HTTP |
| `ADMIN_EMAIL` | `admin@cinema.local` | Адрес администратора при инициализации |
| `ADMIN_PASSWORD` | `Admin123!` | Пароль администратора при инициализации |
| `SESSION_HOURS` | `8` | Срок действия входа |
| `BOOKING_HOLD_MINUTES` | `15` | Срок неоплаченной брони |
| `COOKIE_SECURE` | `0` | Установить `1` при работе только через HTTPS |

Пример настроек находится в [.env.example](.env.example). Файл `.env` приложение автоматически не читает: значения передаются средствами оболочки, Docker Compose или среды развёртывания.

## Проверка

```bash
python3 -m unittest discover -s tests -v
```

На Windows используйте `python` вместо `python3`.

Для нагрузочной проверки списка фильмов запустите приложение и выполните:

```bash
python scripts/load_test.py --url http://127.0.0.1:8000/api/movies --requests 200 --concurrency 20
```

Проверка доступности: `python scripts/check_health.py`.

Демонстрация GET, POST, PUT, PATCH и DELETE: `python scripts/demo_api.py`. Она создаёт тестового пользователя, скрытый после проверки фильм и отменённую бронь в текущей базе. Используйте учебные данные. Для другого пароля администратора задайте `ADMIN_PASSWORD` в оболочке.

## Структура

- `cinema` — сервер, бизнес-правила, безопасность и доступ к данным;
- `static` — адаптивный интерфейс на HTML, CSS и JavaScript;
- `database/schema.sql` — физическая схема SQLite, ограничения и индексы;
- `docs` — требования, план, диаграммы, архитектура и OpenAPI;
- `tests` — модульные и интеграционные тесты;
- `reports` — единый отчёт с разделами по занятиям 1–12;
- `Dockerfile` и `docker-compose.yml` — воспроизводимый запуск.
